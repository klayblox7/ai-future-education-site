# AI 미래교육원 홈페이지 — 업체 인계 안내

## 목적

이 묶음은 AI 미래교육원 홈페이지, 강의별 긴 랜딩 이미지, 신청 양식, 관리자 기능을 기존 홈페이지 운영 업체가 자체 도메인과 서버에 적용하기 위한 인계본입니다. **현재 여유톡 홈페이지와 별도 브랜드**로 운영할 주소와 메뉴 연결 방식은 업체와 결정해 주세요.

## 파일 구성

| 경로 | 내용 |
| --- | --- |
| `html-site/` | 정적 HTML, CSS, JavaScript, 이미지. 기존 사이트에 화면을 이식하거나 자체 백엔드에 연결할 때 사용합니다. |
| `html-site/public-content.json` | 공개 강의·후기 초기 데이터. 강의 ID는 상세 페이지와 신청 데이터의 연결 키입니다. |
| `node-app/` | 현재 작동하는 Node.js 24 서버, SQLite DB, 이미지 업로드, 관리자, 신청·문의 접수 구현. |
| `FORM-API.md` | 업체가 PHP 등 다른 서버 기술로 구현할 때 필요한 입력 항목과 응답 규칙. |
| `SHA256SUMS.txt` | 인계 파일 무결성 확인용 SHA-256 목록. |

## 적용 방법 1 — 기존 Node.js 구현 사용

업체 서버가 Node.js 24를 실행하고 영구 저장 디렉터리를 제공할 수 있다면 `node-app/`을 그대로 배포할 수 있습니다.

1. `node-app/`을 서버에 올립니다. 운영 환경에 `ADMIN_PASSWORD`(새로 만든 12자 이상 비밀번호), `PUBLIC_ORIGIN`(최종 HTTPS 주소), `DATA_DIR`(서버 재시작·배포 후에도 보존되는 디렉터리)을 설정합니다. 로컬 테스트 비밀번호는 사용하지 않습니다.
2. `node-app/`에서 `npm start`를 실행합니다. 별도 npm 패키지 설치는 필요하지 않습니다. `Dockerfile`도 함께 제공됩니다.
3. 첫 실행 시 `seed/public-content.json`과 공개 이미지로 데이터베이스가 생성됩니다. 기존 컴퓨터의 신청자 DB와 관리자 비밀번호는 이 묶음에 포함되지 않습니다.
4. 도메인의 HTTPS 요청을 Node 서버로 연결합니다. `/`, `/lectures/{id}`, `/privacy`, `/admin`, `/registrations`, `/inquiries`, `/uploads/{파일명}` 경로가 같은 출처에서 동작해야 합니다.
5. 운영자는 `/admin`에서 강의·이미지·후기를 관리하고 신청자 목록과 CSV를 확인합니다. `DATA_DIR` 전체를 별도 저장소에 정기 백업하세요.

## 적용 방법 2 — 업체의 기존 서버 기술로 연결

업체가 PHP/MySQL 등 자체 기술을 사용할 경우 `html-site/` 내용을 웹 루트 또는 하위 경로에 올리고 `FORM-API.md`대로 서버와 DB를 연결해 주세요. 링크와 자산 경로는 상대 경로라 하위 경로에서도 표시됩니다. 강의 추가·수정·삭제 및 후기 관리 화면은 `html-site/`에 포함되지 않으므로, 업체 기술로 관리자 화면을 구현하거나 `node-app/`을 별도로 실행해야 합니다.

**HTML 파일만 올리면 신청자 정보가 저장되지 않습니다.** `POST registrations`, `POST inquiries`, DB 저장, 중복 방지, 관리자 인증, CSV 내보내기를 연결하고 실제 저장 확인까지 마친 뒤 광고 URL로 사용해 주세요. 화면의 신청 완료 문구는 서버가 저장에 성공한 뒤에만 표시해야 합니다.

## 광고·행사 운영 확인 사항

- 광고 URL은 최종 HTTPS 도메인의 강의 상세 페이지로 연결합니다. 예: `/lectures/1/?utm_source=instagram&utm_medium=paid_social&utm_campaign=class-1`.
- UTM 5개 값은 브라우저에서 신청서의 숨김 입력에 반영됩니다. 업체는 서버에서 다시 검증해 신청 DB에 저장해 주세요. 이용자가 직접 선택하는 `referral_source`도 별도 보관합니다.
- 동일 강의에 같은 휴대전화번호로 다시 신청하는 경우에는 중복 안내를 표시합니다. 자체 DB로 구현할 때는 DB 수준의 중복 방지도 적용해 주세요.
- 신청자 명단은 권한 있는 운영자만 확인·다운로드할 수 있어야 합니다. 저장 데이터, 업로드 이미지, 백업 파일이 웹에서 직접 노출되지 않도록 설정해 주세요.
- 개인정보처리방침의 운영사, 수집 항목, 보유 기간, 위탁·호스팅 내용 및 동의 문구를 실제 운영 방식에 맞게 업체와 최종 확인해 주세요. 현재 문구를 그대로 확정된 법률 문서로 간주하지 마세요.
- 행사 날짜·장소·신청 인원·사진과 실제 강의 내용이 광고 시작 전에 일치하는지 확인해 주세요. 제공된 공개 강의는 현재 2건입니다.

## 업체 검수 순서

1. 모바일과 PC에서 홈페이지, 강의 상세 2개, 후기 사진, 개인정보처리방침, 메뉴·링크를 확인합니다.
2. 테스트용 신청 1건과 문의 1건을 보내 DB와 관리자 목록에 나타나는지 확인합니다.
3. 동일 번호로 같은 강의를 다시 신청해 중복 차단을 확인합니다.
4. 인스타그램·유튜브 테스트 URL의 UTM 값이 DB와 CSV에 남는지 확인합니다.
5. CSV 파일을 내려받아 한글·전화번호·광고 캠페인이 정상 표시되는지 확인합니다.
6. 테스트 신청 데이터를 삭제하고 백업·복원 방법을 확인한 뒤 광고를 시작합니다.

## 전달 시 유의

이 인계본에는 `.env.local`, 실제 관리자 비밀번호, 신청자·문의 DB가 들어 있지 않습니다. GitHub Pages의 기존 공유 링크는 화면 확인용이며 신청 DB와 관리자 기능을 제공하지 않습니다.
